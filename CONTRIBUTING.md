# Вклад в разработку GigaCleaner

Спасибо, что хотите помочь проекту! Это руководство описывает, как прислать изменения так, чтобы их было легко проверить и принять.

## Начало

1. Сделайте **fork** репозитория (`TIZZ13/GigaCleaner`).
2. Создайте ветку от `main` с говорящим именем: `feature/название`, `fix/название` или `docs/название`.
3. Вносите изменения маленькими осмысленными коммитами.

## Что принимается

- Исправления ошибок и опечаток;
- Новые сценарии очистки **только по белому списку** (безопасность превыше всего);
- Улучшения интерфейса и архитектуры;
- Переводы и документация.

## Что не принимается

- Изменения, которые отключают проверки белого списка или проверку безопасности;
- Удаление существующих тестов без замены;
- Некорректные данные в реестре/путях без проверки.

## Сборка и проверка

```bash
# проект должен собираться без ошибок
dotnet build -c Release

# альтернативные сборки не должны падать
dotnet publish -c Release -p:PublishProfile=PortableSingleFile
```

Перед pull request убедитесь, что:

- код собирается в `Release`;
- не добавлены новые зависимости без необходимости;
- изменения не ломают тёмную/светлую тему;
- при изменении установщика `installer.iss` он компилируется (Inno Setup 6.7+).

## Pull request

- Дайте PR **понятное описание**: что меняется и зачем;
- Привяжите связанный issue, если есть (например, `Closes #12`);
- Не сливайте несколько несвязанных изменений в один PR;
- В заголовке кратко и по делу: `fix: путь к %TEMP% при наличии пробелов`.

## Код-стайл

- Используйте возможности C# 12 / .NET 8;
- Следуйте стилю соседнего кода (именование, интервалы, комментарии);
- Не добавляйте комментарии, которые повторяют код (если это не объяснение «почему»).

## Тестирование

Ручные сценарии, которые надо прогнать перед PR:

1. Сканирование и очистка (безопасные пути, отчёт);
2. Очистка реестра с созданием точки восстановления;
3. Тихий запуск `--silent`;
4. Уведомления (если были изменения в `Notifier`).

Если замечаете регрессию — опишите её в PR, не оставляйте молча.

## Вопросы

Открывайте [issue](https://github.com/TIZZ13/GigaCleaner/issues) — короткий вопрос лучше длинного молчания.
